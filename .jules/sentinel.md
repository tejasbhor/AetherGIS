## 2024-07-02 - Fix XSS in Manual HTML Rendering
**Vulnerability:** Cross-Site Scripting (XSS) vulnerability was found in the `backend/app/services/report_service.py` where manual string formatting via f-strings was used to generate an HTML report. The dynamic variables representing dictionary fields inputted directly into HTML templates were not escaped properly.
**Learning:** Python f-strings don't automatically sanitize injected data for HTML. Direct string replacement into HTML contexts can easily yield severe security vulnerabilities if variables contain user-controlled payload elements like `<script>` or unescaped entities, unlike traditional template engines such as Jinja2 which handle automatic escaping.
**Prevention:** If generating HTML or any form of templated response from backend code using string formatting manually, wrap string representations of user-supplied or dynamic properties inside the `html.escape()` method. When slicing or truncating strings, ensure the truncation happens *before* applying the escape logic.
