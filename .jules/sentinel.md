## 2024-06-07 - XSS in Manual HTML Templating
**Vulnerability:** Cross-Site Scripting (XSS) vulnerability found in `backend/app/services/report_service.py` due to manual HTML string building using f-strings without escaping user-controlled inputs like `layer_id`, `data_source`, `error_msg`, and various diagnostic fields.
**Learning:** Python does not automatically escape f-strings like modern templating engines (e.g., Jinja2, React). Furthermore, when truncating strings to be inserted into HTML, the string MUST be truncated *before* applying `html.escape()`. Slicing an already escaped string could split an HTML entity (e.g. `&quot;`) in half, generating malformed HTML output. Also, avoid naming HTML string variables `html` when using the `html` standard library module, to prevent shadowing.
**Prevention:** Always use `html.escape()` around any user-controlled input injected into manual HTML strings. Apply data operations (like truncating, string formatting) to the raw string first, and only wrap the final string in `html.escape()` just before adding it to the HTML template. Use distinct variable names like `report_html` instead of `html` to avoid shadowing.
