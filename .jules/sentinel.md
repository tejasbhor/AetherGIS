## 2024-05-18 - [HIGH] XSS Vulnerabilities in Auto-Report Generation

**Vulnerability:** XSS (Cross-Site Scripting) vulnerabilities were found in `backend/app/services/report_service.py` where user-controlled variables (`job_id`, `layer_id`, `data_source`, `status`, `error_msg`, etc.) were directly interpolated into an HTML string using Python f-strings without proper HTML escaping.

**Learning:** Since the backend generates HTML reports manually using f-strings and lacks an automatic template engine like Jinja2 with auto-escaping, we must explicitly apply `html.escape()` to all dynamic or user-controlled variables. Additionally, when escaping HTML strings that require truncation (like `job_id[:16]`), the string must be sliced *before* applying `html.escape()` (`html.escape(str(job_id)[:16])`). If slicing is applied after escaping (`html.escape(str(job_id))[:16]`), it could truncate the string in the middle of an HTML entity (e.g., `&am` instead of `&amp;`), leading to malformed HTML and potential rendering issues or even bypasses. When using `import html`, avoid naming local string variables `html` to prevent shadowing the standard library module, which causes `AttributeError` when trying to call `html.escape()`.

**Prevention:** Always use a templating engine with auto-escaping (like Jinja2) when generating HTML, rather than raw f-strings. If manual f-string interpolation is necessary, establish a strict pattern of wrapping all dynamic variables in `html.escape()`. Ensure string slicing is applied to the inner string before passing it to `html.escape()`. Use descriptive variable names like `html_content` or `report_html` instead of `html` to avoid shadowing Python standard library modules.
