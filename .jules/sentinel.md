## 2025-03-09 - HTML Entity Injection in Raw HTML Templates
**Vulnerability:** XSS vulnerability found in `backend/app/services/report_service.py` where dynamic strings from external sources (e.g., job payloads, warnings) were injected directly into an f-string generating raw HTML output.
**Learning:** Python f-strings used for templating have no built-in security mechanisms and do not auto-escape values. Even backend report generation modules can be entry points for XSS if raw strings are directly rendered and viewed in a browser. Additionally, using standard `import html` and a variable named `html` creates shadowing bugs, and truncation must occur *before* HTML escaping.
**Prevention:** Always use `from html import escape as html_escape` and explicitly apply `html_escape(str(value))` to user or external inputs before concatenating them into HTML f-strings. If a template engine with auto-escaping (like Jinja2) is not used, strict manual validation and encoding are required.
