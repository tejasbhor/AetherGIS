## 2026-06-04 - [Fix XSS Vulnerability in Report Service]
**Vulnerability:** Cross-Site Scripting (XSS) vulnerability found in `backend/app/services/report_service.py` where untrusted user input was interpolated directly into an HTML report using f-strings without proper HTML escaping. Variables like `job_id`, `layer_id`, `data_source` and potentially user-controlled elements within lists (`alerts`, `trajectories`) could execute malicious scripts if viewed in a browser.
**Learning:** This occurred because the backend manualy generates HTML reports via raw f-strings instead of a proper templating engine (like Jinja2) that implements automatic escaping. In such cases, escaping must be handled manually. Note that variables must be explicitly cast to strings (e.g. `html.escape(str(variable))`) before applying `html.escape()` and truncation logic should be applied *before* the escaping is performed.
**Prevention:** Always use `html.escape()` for user-controlled strings in raw HTML generation or switch to a templating engine with automatic escaping.
