## 2024-05-24 - [Fix XSS vulnerability in HTML report generation]
**Vulnerability:** The HTML report generation manually composed HTML strings in Python f-strings without escaping dynamically injected user-controlled variables. This could lead to XSS vulnerabilities if variables such as layer_id, job_id, or error messages contained malicious HTML code.
**Learning:** In backend reporting modules generating raw HTML via strings, automatic HTML escaping (like Jinja provides) is missing. Moreover, when importing `html` from the Python standard library for `html.escape`, one must be careful not to shadow the imported module with a local variable named `html` as it causes reference errors. Also, string slicing for truncation must occur before HTML escaping to avoid splitting HTML entities.
**Prevention:** Always use `html.escape(str(val))` on dynamically injected values when manually building HTML strings in Python. Avoid naming string variables `html` when using the `html` standard module. Apply truncation directly to the raw string before it is escaped.
