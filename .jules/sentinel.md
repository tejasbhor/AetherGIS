## 2025-02-24 - Fix XSS Vulnerability in HTML Report Generator
**Vulnerability:** A Cross-Site Scripting (XSS) vulnerability was found in the `backend/app/services/report_service.py` where user-controlled input variables, such as `job_id`, `layer_id`, and `alerts` objects, were passed directly to a raw HTML template string via an f-string without being escaped.
**Learning:** In the current application structure, HTML templates are generated manually via f-strings rather than template engines like Jinja2 which have auto-escaping enabled by default. Thus, any dynamic inputs that bypass standard input filtering could be rendered to execute arbitrary scripts in the final report.
**Prevention:** Always use the `html.escape` method explicitly on dynamic inputs, and to ensure non-string types do not cause TypeErrors, wrap the object evaluation inside a `str()` call first (e.g., `html.escape(str(val))`). For string slices, slicing before the string escape ensures valid HTML entity formatting (e.g., `html.escape(str(val)[:140])`).
