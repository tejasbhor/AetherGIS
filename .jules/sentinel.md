## 2024-06-16 - Prevent XSS in manual HTML report generation
**Vulnerability:** XSS vulnerability through manual HTML string formatting (f-strings) where dynamically injected dictionary values (like error messages, descriptions, IDs) were not escaped.
**Learning:** When generating HTML manually without a template engine like Jinja2 that provides automatic contextual escaping, any injected data poses a significant cross-site scripting (XSS) risk. Moreover, dynamically obtained values (e.g. from dict.get()) might return None or non-string types which could cause TypeErrors if passed directly to `html.escape`. Also, if slicing is necessary, it must be performed before escaping to prevent malformed HTML entities.
**Prevention:** Always use `html.escape(str(value))` to escape user-controlled or dynamically retrieved values before embedding them in an HTML string. Ensure type safety by casting to `str()` and perform any length truncations before the escaping function is called.
