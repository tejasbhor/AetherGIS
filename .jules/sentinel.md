## 2024-05-24 - [Fix XSS vulnerability in HTML report generation]
**Vulnerability:** The HTML report generation in `backend/app/services/report_service.py` directly interpolated string templates without escaping variables like `job_id`, `data_source`, and `error_msg`, creating a severe Cross-Site Scripting (XSS) vulnerability.
**Learning:** Manual HTML string generation is error-prone. The `html` variable name overshadowed the python `html` module creating difficulty while using `html.escape`. Also, temporary patching scripts used during development shouldn't be tracked or committed to avoid polluting the codebase.
**Prevention:** Use a safe HTML templating engine (like Jinja2) whenever possible. If manual generation is necessary, use a centralized `_esc` helper function, escape all dynamic variables, slice strings before escaping them, and rename variables that conflict with python built-ins. Ensure build artifacts like lock files (`uv.lock`) are restored if altered inadvertently.
