## 2025-02-12 - Cross-Site Scripting (XSS) in HTML Report Generation

**Vulnerability:** AetherGIS's backend generates comprehensive HTML technical reports via the `report_service.py` service. It was creating HTML simply by using Python f-strings without properly escaping variables controlled by the user or upstream processing systems (e.g. `job_id`, `layer_id`, `data_source`, and contents within logs and arrays like alerts and issue trajectories). An attacker could craft a malicious `job_id` or similar input which, when viewing the report, would execute unsanitized JS in a victim's browser.
**Learning:** Due to the absence of a proper template engine (like Jinja2) that provides automatic contextual escaping, relying on f-strings meant all interpolation lacked protection against script injection. The code shadowed the built-in `html` library with a local string variable named `html` tracking the report output, which complicated fixing.
**Prevention:** Always use `html.escape()` on user-controlled inputs when manually formatting HTML strings in Python using f-strings. When truncating strings, ensure the truncation slice applies *before* HTML escaping the resulting string to avoid generating malformed HTML tags. Alternatively, utilize an established template engine (e.g., Jinja2) that handles automatic contextual escaping by default. Avoid shadowing standard libraries like `html` with local variables.
